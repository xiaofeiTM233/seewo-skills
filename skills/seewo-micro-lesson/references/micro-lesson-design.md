# 微课设计

先明确学生学完能独立完成的一件事。已给设计时，保留教师指定的顺序、必讲内容和活动，仅补关键缺口。主题过宽时先收窄学习任务；只有学段、教材版本或使用场景会实质改变内容才询问。

**查依据。** 优先使用用户明确指定的课页和真实例题；没有课页时用可用检索定位适用教材、出版社目录或可靠原文。引用课标时按学科、学段、版次核对官方原文，记录出处及它支持的教学决定。目录只能确认章节，搜索摘要不能充当课文或题图。区分原例与自编变式；关键条件无法核实时换用已核实的例子或请用户补充。无需创建云教案。

**写给独立学习的学生。** 用学生能听懂的一句话提出问题，确定示范停在哪里、学生接下来做什么、答案何时揭晓、怎样自己核查。保留必要的方法理由与例题条件。同一案例前后沿用对象和数据。对象变化时同步更新画面和说明，学生开始下一题前收起上一题的解答。屏幕逐步呈现当前对象与短提示，旁白解释关系，纸笔或暂停任务留在课内。

**主动找值得做的互动。** 各学科都按教学目标判断，无需请老师选择页面类型。若独立操作能帮助学生发现规律、检验预测或核查理解，在 `lesson_design.body` 写清“学生改变什么 → 观察到什么可重复的差异 → 据此作什么判断 → 怎样核查”，并注明优先用 Lab，同一次探索和作答放在同页。例如固定指针中心，让学生拖动终点，用扫过的格数验证转角。独立朗读、圈出诗句和复述定义通常用讲解页就够。证据依赖精确原图时使用可验证的真实素材或换例。

找到这样的核心活动时，在 `supplemental_requirements.interaction_policy` 传入 `{"mode":"optional","min_tool_pages":1}`。这会让 Planning 在授权和预算内优先安排互动，生成失败时保留同一教学目标的讲解和自查。没有合适活动时沿用默认策略。老师要求“拖动滑片”“自己拼图”等具体教学动作时，同样按此方式优先规划；仅在用户明确表示无法交付真实操作就不要出课时使用 `required_tool_types`。

**从教辅设计中借鉴的做法**

- 鱼图减法：同一组红黑鱼，完整示范求红鱼，让学生自己列式求黑鱼，再用加法反查。示范过的答案不再当作独立发现。
- 牛奶兑水：同一只杯子，喝一半、兑满、再喝一半，每次先让学生指出奶和水各有多少，再显示当前成分。每次只更新一个状态。
- 周角：终态画面看不出零转与一圈的区别，保留转动轨迹；天气统计则用同一张表和条形图核验总天数即可。
- 估测一亿张纸的厚度：先让学生选样本并记录测量条件，再按同一单位放大。统计课比较两条收入曲线时，让学生算逐年差；两条线都上升，差距也可能缩小。把容易误判的地方设计成学生能核查的问题。
- 七巧板：让学生先看外轮廓再拼，最后亮分块线，用“恰三块、无缝、无重叠”反馈。若没有经过核对的拼法图，不承诺复现教辅原题。

**交给生成。** 输出 `lesson_design.topic`（至多200字符）、`body`（至多12000字符，包含依据、主问题、示范与学生任务、反馈、画面和可选 Lab）和 `required_points`（1～8条，每条至多300字符，可在成品中检查）。老师的额外偏好另放补充要求。上限是接口容量，不要求写满。简要展示设计重点，用户要求审稿时才等待。生成、授权、工作区选择和重试由微课创作入口处理。
