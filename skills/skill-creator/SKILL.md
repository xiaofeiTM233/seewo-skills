# Skill Creator

在原生 codemode 中通过 `tools` 调用 `skills_author`，参数直接传结构化对象。需要发现或核对参数时，在 codemode 内使用 `searchTools` / `describeTool`；已有适用声明时直接复用。领域工具直接返回业务 DTO，按实际字段和业务分页参数读取。每次调用仍由 Host 校验授权、撤销和业务确认；结果未知时先查询或回读，不能重放已完成写入。

把用户希望重复使用的做法整理为 Skill。通过 `tools.skills_author` 管理草稿与发布，不直接写 `~/.easinote`，不通过 Bash 安装。

## 设计

- 先理解任务、触发场景、输入与期望输出；已有信息足够就直接创建，只有影响结果的缺失信息才需要询问。
- 默认只写 `SKILL.md`。仅保留会改变 Agent 决策的领域知识、关键步骤和真实约束，不重复常识、不扩展用户授权范围。
- 按需要添加 `references/`（详细资料）、`assets/`（输出模板）；展示信息写在 `SKILL.md` frontmatter 的 `displayName`、`description_cn` 和字符串 `metadata` 中。不要为凑目录创建空文件。
- 只有重复变换、计算或确定性执行能明显提高可靠性时才添加脚本，不把应由 Agent 判断的教学流程硬编码。
- 用户是老师，不假设电脑有 Python、Node、Shell、npm 包或开发工具。新建脚本使用应用内置 Node 支持的 `.mjs`、`.cjs` 或 `.js`，只依赖 Node 内置模块及技能内文件；优先 `.mjs` 明确模块类型。实际调用用 `node <技能根目录>/scripts/<文件名>`，路径含空格时加引号，Node 由应用提供。
- 需要外部服务或复杂运行环境时优先使用已有托管能力；在技能说明中引用已经可用的工具；连接器依赖由连接器包的 `config.yaml` 与 `mcp.json` 声明，不要在脚本中安装包、下载解释器或启动 `npx -y`。

## 创建与验证

1. 调用 `create` 创建草稿，名称使用小写字母、数字和连字符。
2. 用 `write_files` 写入所需文件，使用结构化 `files` 数组，每项包含 `path`、`content` 和可选 `encoding`。所有相对链接从 Skill 根目录解析。
3. 调用 `validate` 检查结构与支持的脚本运行时。无脚本技能通过后即可进入发布预览，不需要构造脚本或测试来凑流程。
4. 对新增或修改脚本的关键入口调用 `test`，用真实输入核对输出、边界条件和失败行为。测试在应用提供的独立受限环境运行，与会话权限模式无关；不能联网，只能写测试输出目录（测试进程的 `HOME`）。文件输出脚本应接受输出目录参数，不写死测试路径。
5. 结构校验不证明教学效果，脚本退出成功也不证明结果正确；按任务需要检查实际产物。复杂技能可用代表性任务进一步验证，普通创建不强制多 Agent 评估。

若校验报告不支持的运行时，改用受支持的实现或已有能力，不要求老师安装 Python。若报告测试环境不可用，保留草稿并准确说明应用环境问题；没有环境变化就不重复测试，不承诺“等沙箱恢复”，不把普通 Bash 执行当成受限测试通过。

## 发布与迭代

草稿达到 `ready` 后调用 `prepare_publish`，通俗说明预览中的文件、脚本、依赖、权限和冲突。这个动作只返回预览数据，不展示确认界面。

说明改动后继续调用 `commit_publish`：传入同一 `draft_id`，将预览返回的 `planId`、`planDigest` 原样填入 `plan_id`、`plan_digest`。这次调用由 Host 发出确认请求，桌面显示“确认发布技能”并等待用户批准，批准后才实际发布；不要停在预览后让用户点击尚未创建的确认卡片。

按调用的实际结果说明状态：用户拒绝、取消或确认超时时保留草稿并说明未发布。`commit_publish` 返回 `onboarding` 时表示已批准并交给 Host 等待安全提交，简短说明后结束本轮，不重复发起发布或要求用户再次点击。Host 自动把实际结果交回原对话，收到完成结果后才说明发布成功。计划失效时重新获取预览和确认。新建技能发布后默认启用；更新保留用户原有启停选择，新 Run 使用当前能力绑定。

修改用户创建的 Skill 时用 `clone_installed` 创建新 revision；第三方 Skill 默认复制为未占用名称的用户副本。用户明确要求更新已安装原技能时，可用保留原名的克隆草稿，预览必须明确提示将更新的原技能和版本，再由用户确认。根据真实使用或明确失败作局部改进，不因个别案例不断添加通用限制。

格式和元数据字段见 [references/skill-format.md](references/skill-format.md)。
