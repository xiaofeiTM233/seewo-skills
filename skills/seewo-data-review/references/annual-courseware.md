# 每年值得回顾的课件

为回顾时间线中的每一年，读取该年最近更新、当前版本号最高的前 20 份个人普通课件，辅助分析各阶段的主题和代表作品。这里只读取摘要，不读取正文或遍历目录。

## 年份与取数

1. H5 运行开始时执行一次 `store("seewo-data-review:annual-courseware", null)`，清除上一轮年度缓存；同轮不再重置，待办运行不执行。先完成原有半年采集；若已限流，年度查询随之停止。
2. 依据本轮已确认的回顾时间线确定最早年份，连续覆盖至今年；用户明确限定回顾区间时遵循该区间。云课件起点参考 statistics 的有效 earliest_created 和 yearly，不使用缺失、异常或未来年份推断起点。**yearly 是创建年份，不能只查询其中非空的年份**；中间没有创建记录的年份也可能有旧课件更新。没有可信年份依据时省略年度分析，不猜测起点。
3. 将本轮固定年份数组写入 `store("seewo-data-review:annual-courseware-years", [2024, 2025, 2026])`，示例年份必须换成本轮真实范围。query 不支持负时间下界；1970 年前的年份不查询，说明该部分无法覆盖。statistics.total 明确为 0 时不查询云课件年份。
4. 读取 `scripts/collect-annual-courseware.js`，将正文作为 codemode 代码执行。脚本按 Asia/Shanghai 自然年使用 `[当年1月1日00:00, 次年1月1日00:00)`，今年上界截到本轮固定时刻；1970 年下界取接口可接受的 0。每年只调用一次 `query`，传 `order_by:"version", limit:20, offset:0`，不因 has_more=true 继续翻页。
5. 每个年份最多返回 20 份；年度额外请求预算等于有效年份数，与半年最多五页独立。年份、排序和数量固定后不换条件补查；再次执行只复用本轮缓存。参数不受支持、业务失败或限流时保留成功年份并停止，不回退全库扫描或本地重算排行榜。
6. 脚本按年份保留窗口、作品、rankingComplete、rangeExhausted 和停止原因。返回满 20 份且无重复、无效记录或乱序时，即使 has_more=true 也已取得年度前 20；不足 20 份时，只有 has_more=false 才能证明该年候选已取完。异常只限制对应年份的结论，不影响其他成功年份或全库统计。

缓存保存在 `load("seewo-data-review:annual-courseware")`。需要作品字段时直接复用，不另开名称搜索或目录查询。

## 分析与表达

- **准确范围**：这是按课件当前保留的最近更新时间归年的候选集，再按当前版本号倒序取前 20；不是该年所有历史更新，也不是该年修改次数。跨年继续更新的同一课件只会归到当前最后更新时间所在年份，不能据此还原它以前出现过的年份。
- **作品选择**：每年参考全部已取候选，从名称及本轮已有真实材料中选 1–3 份有代表性的作品，描述有依据的教学主题或与本地经历的联系。名称不够明确时只展示作品名，不声称读过正文。
- **主题变化**：可以比较「这些代表作品涉及的主题」，不能把 20 份样本计算成全年的学科占比、工作量或投入强度。年度候选和半年近期样本各有范围，不混合计数。
- **完整与部分**：rankingComplete=true 时可称「这一年最近更新过、当前版本号较高的一批课件」；否则只称「本次取得的代表作品」，并说明该年的资料未完整取得。未查询、读取失败和成功空结果分别保留，不补零，不推断当年没有备课。
- **页面位置**：融入「我一路做过的事」对应年份卡片，增加 1–3 个作品及简短主题依据；不把 20 份全部铺进页面，不新增独立时间线。工作重心可以引用年度代表作与半年证据，但分别说明阶段范围。
- **老师可见说明**：「这些作品按最近一次更新时间归年，参考当前云端版本记录挑选，不代表当年的修改次数。」只需在时间线附近解释一次。

可用句式：「这一年最近更新的课件中，《名称》留下的云端版本记录较多，可作为这一阶段的代表作品回顾。」不写「这一年修改最多」「当年改了 X 次」「每年最常使用」。
