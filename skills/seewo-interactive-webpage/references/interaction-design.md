# 教学目标与交互

先用一句话明确学生要理解或练习的内容，再列出可操作输入、内部状态和可见输出。一个网页聚焦一个主场景；操作、状态、结论保持对应，避免用无关动画代替概念表达。

| 类型     | 必须定义的行为                                       |
| -------- | ---------------------------------------------------- |
| 参数模拟 | 参数范围、单位、初始值、边界值、结果的数学/科学依据  |
| 拖拽分类 | 合法目标、错误反馈、已放入对象的返回或撤销、点击替代 |
| 步骤推演 | 当前步骤、上一步/下一步、不可达状态、重置            |
| 答题计分 | 判定依据、防重复得分、提交反馈、下一题和清空规则     |
| 动画实验 | 开始/暂停/重置、时间步长、有界更新、后台标签页行为   |

布局默认主场景、操作区和反馈区在主视区内。使用弹性布局、相对尺寸、合理最小宽度；窄屏和放大字体时允许滚动，不隐藏核心内容。按钮、拖拽对象有清晰触控区域、焦点状态和文字说明，不仅依赖颜色。

## 视觉场景

先确定适合主题与学段的一套视觉语言：主视觉、主色/强调色、字级、控件状态和材质。具象主题用图片建立可辨认的教学场景，DOM/SVG/Canvas 承载可操作对象与准确标注。避免所有主题都落成白底圆角卡片、细虚线和编号圆点；几何图形应表达知识关系，不承担它无法表达的人物与场景细节。

主场景占据主要展示空间，标题简短，次要规则收纳，反馈靠近当前操作。不要用大块空白占位、巨大的统计面板挤压实际教学内容。图片上的文字使用有足够对比度的衬底，装饰图层不接管点击；图片与热点用同一坐标容器缩放，不能在窗口变化后错位。

例如取经路线页：山水插画做低对比底图，准确的站点名称、顺序、连线和状态用独立 SVG/DOM 层表现；选中站点时显示情节反馈与人物/情境图。图片不决定真实路线或答案，也不把交互烧进背景。函数探索页则以清晰坐标、曲线、变化反馈为主，不强行加无关背景插画。

## 实现要求

鼠标、笔和触控统一使用 Pointer Events；处理 pointercancel，结束拖拽时释放捕获。Canvas 按 CSS 容器尺寸和 devicePixelRatio 调整绘图缓冲，在 resize 后重绘。状态集中保存并由同一个 render/update 路径更新，重置恢复初始状态、计时器、分数、选择和图片状态。

随机互动记录随机种子或说明不可复现的随机行为；普通刷新重置运行状态。不使用 localStorage、Cookie 或后台同步保存课堂数据。页面不访问网络 API。事实性图片或科学图示核对正确性，AI 配图只承担可验证的视觉辅助。

图片加载期间有占位，加载失败显示可理解反馈。Canvas 读取像素、截图或导出必须先确认 CDN CORS；否则选择离线内嵌版。不能仅因普通 img 能显示就宣称 Canvas 可导出。
