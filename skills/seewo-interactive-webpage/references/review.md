# 页面验收

直接检查最终 HTML 的教学事实、题干、答案和主要状态。运行一次 `check --file <HTML>`，修复报错后重跑。它不执行页面，不证明视觉或交互已通过。

## 一轮核心验收

有现成浏览器能力时，默认检查一个课堂宽屏和一个窄屏：

- 看截图：图片加载、主题可辨、文字清晰、关键按钮可见，没有明显遮挡或横向溢出。
- 每种交互类型走一条正常路径、一次错误或边界输入、一次重置。计分验证不能重复累加；拖拽有点击/触控替代路径；动画能暂停和重置。
- 查看运行错误；外链或 module 脚本在浏览器中验证可用。只有涉及 Canvas 读像素或导出时检查 CORS。

使用现有浏览器工具或简短的检查脚本，不默认编写覆盖全部题目、全部分数和大量视口的自动化测试套件。不以断言数量作为完成标准。打开文件时使用最终 HTML 的绝对路径，避免切换到依赖目录后解析成错误路径。没有可用浏览器时说明限制，不为本次网页另搭完整测试环境。

## 修复与停止

真实运行错误、错误判分、无法重置或明显遮挡需要修复，并复查受影响路径；不要求每次样式调整都重新跑完整关卡和所有尺寸。新增缺陷或用户要求更广覆盖时再扩大验收。

局部修复前读取当前文件中将修改的片段；替换目标必须唯一匹配，不沿用较早版本的 `oldText`。布局调整只改明确的 CSS 规则，不能用跨越 `</style>`、`<script>` 的字符串切片连带删除脚本变量。多处编辑逐项核对匹配；任一项不匹配先停止，重读该片段后再提交，不重写无关页面代码。修改完成后重跑静态校验，并复查受影响的实际交互及运行错误；不要把进程退出 0 当作页面没有 ReferenceError。

图片可见、核心交互正确、重置有效且没有阻断错误或明显布局缺陷后即交付。允许窄屏必要滚动；不为轻微留白、面板高度或非关键裁切反复截图微调，也不为完成验收额外生成长篇测试报告。

按主 Skill 的交付流程，使用一次 `interactiveWebpage.publish` 登记并交付作品，核对回执中的云端保存状态；云端失败或结果未知时使用返回的本地文件入口。只有该工具不可用时才用 `publish_file` 登记本地 HTML。配图、脚本、截图和校验记录只作过程文件，不登记为最终产物。

说明核心交互、联网依赖和实际验证范围。没有浏览器能力时明确“未做浏览器渲染与交互验收”。

不把本次生成过程、测试数量、临时路径和助手选择写成教师的长期偏好。只有用户明确纠正或给出可持续复用的要求时，才按宿主记忆规则更新；不在交付前额外整理制作日志。
