# 图片与公开发布

素材来自用户明确指定的可读文件或 `tools.images_create` 返回的工作区图片，不自动将对话附件物化。默认公有链接交付，已有可用公有链接可以直接引用；选定的本地图片按授权范围用 `upload-image --file` 上传。支持 PNG/JPEG/WebP/GIF，不上传 SVG。不扫描目录或附件数据库，不把内部 handle 当作图片链接。

按用户已授权的范围公开选定图片，沿用宿主执行审批，不另建确认 token。公有链接的持有者可能访问图片；本地删文件不会撤回公有链接。不适合公开的图片直接转成 data URL 内嵌。

## 配图决策与执行

写 HTML 前先确定页面的主视觉，不能先做完整线框页面，再把配图当成可有可无的装饰。复用用户指定或当前作品中质量合格的图片；缺少素材时按下表调用实际可用的 `tools.images_create`，无需等用户说“加图片”。

| 主题                                       | 默认做法                                                                                    |
| ------------------------------------------ | ------------------------------------------------------------------------------------------- |
| 文学故事、人物冒险、历史情境、游戏探索     | `mode:"auto", intent:"creative"` 准备统一风格的场景或人物插画；路线、文字、热点由代码叠加   |
| 动植物识别、文物、真实地理景观             | `mode:"auto", intent:"factual"` 优先真实素材，检查物种/对象是否匹配；不能用虚构插画冒充证据 |
| 几何、函数、受力、光路、电路等精确关系     | 原生 SVG/Canvas 绘制准确且可变的图形；只在情境表达确有帮助时配图，不为凑数生图              |
| 用户已提供合适图片，或明确要求无图、纯矢量 | 复用素材或遵循无图要求，不重复生图                                                          |

先做一张可复用的主视觉，只有教学内容需要区分不同场景时才补图，不按关卡数量分配图片。查看后若对象、清晰度和构图合格就采用；优先用 CSS 控制显示，不为轻微装饰差异、来源标记或追求固定比例自行进入多轮像素修补、裁切和读图。确有尺寸或遮挡问题时集中处理一次，再复查。提示词写清主题、对象、画风、构图、留白、比例、教学用途和不应出现的内容。多图复用同一套风格描述。用户明确要求 AI 生图才使用 `mode:"generate"`；默认 `auto` 沿用工具自身的生成决策与审批，不能为强制生图绕过它。

例如《西游记》取经路线互动页，先调用：

```json
{
	"mode": "auto",
	"intent": "creative",
	"aspect_ratio": "16:9",
	"style": "国风绘本插画，纸本质感，青绿山水与暖赭色",
	"purpose": "取经路线互动页的示意山水底图，路线与站点由网页叠加",
	"prompt": "为中学名著阅读制作西游记取经主题横向场景插画。远景层叠山峦，中景河谷、古道和寺庙，边缘点缀云雾，中央保留大面积低对比浅色空间供网页叠加路线与站点。画面完整精致、层次清晰，适合课堂投屏。不要文字、编号、箭头、现成路线、UI面板或水印；不声称真实地理位置。"
}
```

读取工具返回的工作区图片路径，查看实际图像后决定采用、调整或替换；显示比例不适合时优先调整容器与 object-fit/object-position，不能拉伸图像。通过 `upload-image --file <图片路径>` 取得公有链接后直接引用。不要把整个可交互网页生成为一张图片，也不要依赖生图模型准确绘制文字、公式、地图坐标或站点顺序。

图片准备和 Cstore 发布分别判断：用户明确要求离线、所选图片未获公开授权/不宜公开，或本次实际上传失败时，保留图片并直接转成 data URL 内嵌交付。交付时说明内嵌原因。历史 CDN 延迟或旧环境变量缺失不等于本次上传失败，不因此默认内嵌。仍遵守 HTML 大小预算，必要时缩图。工具未注册、审批拒绝或服务失败才属于配图能力受限；说明真实原因，保留现有素材并做明确的矢量降级，不能声称已生图或已达到插画效果。

## 内置上传与失败处理

入口内置于 `scripts/lib/upload.mjs`，当前固定使用 Bloom **正式环境**，与脚本及 `webpage.mjs --help` 返回的 `policyUrl` 一致：

```text
https://bloom.seewo.com/bloom/api/cstore-public-upload/get-upload-policy
```

无需环境变量、Host 配置或上传/CDN 域名白名单；不会自动跟随 Desktop 的测试/正式环境切换，也不提供运行时端点切换参数。仅允许测试环境上传的任务不执行此正式环境上传命令，按公开授权边界使用本地内嵌交付。按 policy 返回的 formFields/headerFields 组装 multipart，将图片作为 file 上传到 uploadUrl，直接返回 downloadUrl。无需业务 Cookie、Token 或 Cstore 密钥，也不自己计算签名。要求服务端通知的 policy 暂不支持。

只保留 HTTPS、基础协议、文件大小/格式和超时检查，不自动跟随重定向。policy 获取和匿名图片探测默认 30 秒，上传 60 秒。上传后匿名 GET 验证图片类型与 SHA-256；不保存 policy、回执缓存或本地上传状态。

- `verification:passed`：本次匿名探测通过，可以使用返回的 `url`。有效期仍由服务决定，不承诺永久；不要删除 URL 查询参数。
- `ok:true` 但 `verification` 非 passed：服务已返回图片链接，探测失败。保留并检查返回的 URL，不因探测失败立即重传。
- `UPLOAD_RESULT_UNKNOWN`：发送后断连、超时或返回无法确认，云端可能已有对象。停止自动重试，说明情况，再按已有授权决定是否重新执行；脚本不承诺幂等。
- `ACCESS_DENIED` / `POLICY_FAILED` / `UPLOAD_FAILED`：说明失败；可以继续内嵌交付，不导出登录凭据补齐。

脚本一次只处理所选图片；多图逐张上传，将成功链接直接写进 HTML 并复用，不因后续失败重复上传前序图片。公有链接需联网；Canvas 读像素或导出时还需检查匿名 CORS。离线交付由 Agent 直接内嵌图片，不经过构建或导出命令。

### 内嵌时只替换唯一占位符

仅在上述内嵌条件成立时使用。先完成必要的图片缩放/压缩，确定最终字节，再一次性写入；不要从已有 `url(...)` 中按右括号切片，也不要用正则截取、重拼整段 CSS。HTML 中预留一个 `__SELECTED_IMAGE__`，例如 `background-image:url("__SELECTED_IMAGE__")`。保留两侧引号与括号。

下面的纯函数可放在本轮 Node 脚本中。`imageInfo` 复用本技能 `scripts/lib/images.mjs` 的真实格式与尺寸校验；`bytes` 由已授权文件读取，不让模型重写 base64。

```js
function inlineSelectedImage(html, bytes, imageInfo) {
  const marker = "__SELECTED_IMAGE__";
  if (html.split(marker).length !== 2) {
    throw new Error("IMAGE_PLACEHOLDER_MUST_APPEAR_ONCE");
  }
  const { mimeType } = imageInfo(bytes);
  const dataUrl = `data:${mimeType};base64,${bytes.toString("base64")}`;
  return html.replace(marker, () => dataUrl);
}
```

先得到函数返回值，再写回原最终 HTML 路径；断言失败时保持原文件不动。重复调用已内嵌的文件应失败，不自动重建页面。替换后仍执行 `check --file` 与原有浏览器验收；此函数只保证不破坏占位符以外的内容，不能证明整个页面的 CSS 或交互正确。
