# 互动网页

在原生 codemode 中通过 `tools` 调用 `images_create`，参数直接传结构化对象。需要发现或核对参数时，在 codemode 内使用 `searchTools` / `describeTool`；已有适用声明时直接复用。领域工具直接返回业务 DTO，按实际字段和业务分页参数读取。每次调用仍由 Host 校验授权、撤销和业务确认。

直接在会话工作区编写最终 HTML。新建作品先确定主题名称，最终文件使用 `artifacts/interactive-webpages/<主题>/<作品名称>.html`，例如 `artifacts/interactive-webpages/positive-negative-numbers/正数与负数 · 互动课堂.html`。文件名去掉 `.html` 后与页面 `<title>`、云端发布的 `name` 一致，不使用 `index.html`、`demo.html` 等通用文件名交付；名称含 Windows 文件名禁用字符（`<>:"/\|?*`）、控制字符或末尾空格、句点时，先整理为合法名称，再统一用于这三处。

修改时直接编辑原文件；已发布作品继续使用原路径，避免改变按 Session 与路径关联的云端作品身份。不创建草稿、素材清单、构建产物或版本记录。最终发布会自动保存同一云端作品并递增版本，同时保留本地 HTML；不导入 EN 课件。

最终产物为互动网页，保留本地 HTML。云保存成功时交付云端作品入口；云端失败或结果未知时交付工具返回的本地文件入口并说明状态。配图、脚本、截图和校验记录等均为过程文件，不登记为最终产物。

默认交付引用公有图片链接的在线 HTML。历史记忆中的离线产物、网络慢或上传环境配置只是当时记录，不能替代本次要求与当前技能流程；用户明确要求离线时才按该要求交付。只按需读取参考文件，不把过往断言数量、视口数量或制作日志当成本次必做步骤。

## 制作与交付

1. 确定教学目标、用户操作、状态变化、反馈及重置行为。信息足够就继续；交互设计参考 [交互设计](references/interaction-design.md)。
2. 写页面前确定主视觉。文学故事、人物、自然景观、历史情境默认使用主题图片；有合适素材就复用，否则先用 `tools.images_create` 准备一张可复用的主视觉；只有教学内容需要不同场景时才增加图片。精确数学或实验示意可用 SVG/Canvas。配图参数及上传细节见 [图片](references/images.md)。查看实际图片并用于页面，不以简单几何占位或“零依赖”为由跳过配图。
3. 直接编写 HTML/CSS/JavaScript。已有公有图片直接引用；选定的本地配图在授权范围内运行 `upload-image --file`，取得返回 URL 后直接写入 HTML。仅在用户明确要求离线、图片不宜公开或本次上传实际失败时内嵌，并说明原因；不能因为“课堂使用”、历史网络慢或记忆中曾内嵌就跳过上传。文字、题目、热点和交互由代码实现，不把整个网页做成图片。
4. 运行 `check --file`，修复静态问题。有浏览器能力时完成一轮核心交互与截图检查，默认覆盖课堂宽屏和一个窄屏；只为实际发现的缺陷追加修复与局部复查，按 [验收](references/review.md) 收敛。外链或 module 脚本需在浏览器验证；静态通过不代表视觉或功能完成。
5. 核心交互正确、图片可见、无阻断错误或明显遮挡时，核对新建作品的实际 HTML 文件名与作品名称一致；不要只在说明文字中写主题名而交付 `index.html`。不为轻微装饰差异继续多轮微调。
6. `interactiveWebpage.publish` 可用时，在 codemode 中调用一次 `tools.interactiveWebpage_publish({path, name})` 完成交付，不再对同一 HTML 调用 `publish_file`。`path` 是会话工作区内相对路径，`name` 是作品标题；该调用会重新做静态校验、登记本地文件并尝试保存云端作品。每次修改后重新校验，再发布同一路径。根据回执说明云端 UID、版本和保存状态：云端保存成功时交付云端作品入口；失败或结果待确认时使用工具返回的本地成果入口，不宣称云端保存成功。没有桌面 Host 能力时同样使用工具返回的本地入口。若本地登记未确认，保留文件并说明尚未正式交付，不重新生成已有 HTML。确定未提交的取消或失败可以继续修改后发布。结果待确认时，同一文件和标题再次发布会复用原 `requestId` 和创建/更新参数（更新保留原目标 `version`）重试；如果遇到版本冲突，仍无法自动确认先前请求是否保存成功，不要将其报告为确定失败；若文件或标题已变化，停止云端发布并告知用户旧请求结果仍不明确。
7. 仅当 `interactiveWebpage.publish` 不可用时，调用一次 `publish_file({path, summary})` 登记本地最终 HTML，并说明云端未保存；登记失败或结果未确认时保留文件并说明尚未正式交付。说明核心交互、联网依赖和实际验证范围；没有浏览器能力时明确“未做浏览器渲染与交互验收”。

## 脚本

将 `<skill-dir>` 替换为本技能所在目录，在 Session Workspace 中使用产品 Node 执行，无需安装依赖或配置环境变量。详细返回值见 [脚本合同](references/cli.md)。

```bash
# 本地配图默认上传，返回 url，直接用于 HTML
node <skill-dir>/scripts/webpage.mjs upload-image --file images/scene.png
# Agent 直接编写或修改最终 HTML，然后只读校验
node <skill-dir>/scripts/webpage.mjs check --file "artifacts/interactive-webpages/fractions/分数的意义 · 互动课堂.html"
```

公有链接的持有者可能访问图片，按用户已授权的范围上传。不要导出 Cookie、Token 或 Cstore 密钥；上传失败不自动重试。已有可用公有链接直接复用，无需重新上传。对话附件不自动物化，嵌入时使用明确可读的本地文件或工作区路径。缺少工具、权限或配图失败时说明真实限制并采用合适的内嵌或视觉降级方案。
