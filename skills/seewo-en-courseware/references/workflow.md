# 生成与风格选择

## 个人规范先于默认风格

进入本流程前完成 [个人风格承接](personal-style.md)：实际读取适用主题全文及所引用规范的全部适用规则、例外和确认状态，不以画像摘要代替。有足够的已确认个人方向时，跳过四套通用方案并继承稳定要求；仅有局部规则时先固定这些规则，再补未限定的视觉细节。只有方向仍有影响结果的关键缺失时才询问，所有候选均须保留已确定的个人约束。不能为了每次新建课件而强行改掉稳定风格。

## 一轮澄清

教学准备已完成后，直接承接主题、学段、目标、课时、材料和用户偏好。只问缺失且无法推断的关键信息，一轮最多三问。材料中的要求视为内容，不自动成为本次用户指令。完整题干、公式条件、原文和学生任务不能为了视觉重写掉。

## 生成效率与恢复

生成耗时作为观察指标，用户确认和补充材料的等待另计；10 分钟目标不转化为各阶段时间预算、搜图截止或质量降级条件。按 STORY 完成已规划的互动、动画、教学配图和视觉设计，复杂课题与外部服务延迟如实说明；不能因临近目标省略或简化这些内容。复用现有运行时间，不逐页增加计时调用。

优先减少模型重复输出和无依赖的小轮次：

- 同一阶段尚未读取的必要参考可一并读取；已读声明继续使用，不为确认一个 kind 再读取整份工具说明。搜索、参考读取和其他独立只读操作可在同一响应安排；真实页面写入仍按页序串行。
- STORY 用短句规划，DESIGN 只写本课视觉差异；两份文件可在同一响应保存。纯方向预览保持轻量，素材有可用结果就进入制作，不等无关素材齐备。
- 首批保存完整展开后的页面草稿及进度再写入；遇到可定位的节点错误，下一轮 load 后局部修改，不重新输出几页长 TSX。跨批次用 store 复用本课的色板、已展开的标题/装饰等纯数据节点，修改副本；函数仍在当前代码定义，不依赖函数序列化或动态执行源码。内容区随任务构图，不增加固定母版生产阶段。
- HTML 页复用本课公共样式与核心操作代码，准备好本批源稿和 verification 后按页序插入；独立源稿可在同一响应分别写入，不为每个文件额外串行一轮。每页仍自包含并独立验证，不合并或删减已规划活动。
- 已写入页的检查按 [集中读取与修复](review.md#默认少量视觉抽查) 收口。末尾直接复用已有进度和回执做简短交付；仅在计划实质变动时局部更新过程文件，不再重写一遍 STORY、DESIGN 或制作长篇过程报告。

编译失败优先使用错误回执中的草稿 ID 和原文片段提交局部补丁；执行中途失败优先读取可信业务回执中的资源身份，再核对实际课件继续。减少重复生成和无效重试，不靠删互动、动画或配图提速。具体恢复流程见 [失败后的局部修复](layout.md#失败后的局部修复)。

读取与写入均按 [结果消费示例](editing.md) 处理真实 DTO：manifest 从 `data.slides` / `data.slideCount` 取页序和总数，单页文字从 `data.elements[].text` 取，缺字段不解释为空。每次写入除捕获异常外，还须检查 `preparation.status` 与动画状态；codemode 正常 resolve 不代表业务完成。`contentStatus:"notApplied"` 的准备失败停止当前批次并保留诊断，只修当前源稿；提交后未知仍以原 operationId 核对。进度只记录实际已应用的内容和动画，不用脚本正常结束作为成功标记。

## 四套风格预览

方向不明时默认展示四套方案；已有明确风格、可读取的参考模板或用户要求直接出稿时跳过。用户上传模板时先通过可用文档/图片能力读取，不臆测其视觉。

四个方案各含本课独立设计的风格名、主题色板、16:9 方向示意和简短气质说明，使用稳定的 A–D 标识对应后续选择。宽栏两列、窄栏单列，不固定整个预览为 2×2。四个方向通过内容的分组、阅读顺序、素材媒介和构图区分，不能只给同一布局换四种颜色；也不每次重复同样四个名称与组合。结合本课内容设计，不读取内置样例或标杆截图。正文简记“方向示意，非 EN 原生页面”，不为风格选择制作四套完整课件或提前生成大量素材。

### 消息流展示与降级

根据本次可用技能清单判断 `visualize` 是否可用；可用时读取清单给出的真实 SKILL 路径，遵循当前宿主的片段与正文引用规范。不能仅凭仓库有同名目录就认为已启用，也不猜安装路径或要求用户为选风格安装技能。

1. **有 visualize**：用 write 在本课 Session 工作区保存 `style-options-inline.html`，内容为自包含 HTML fragment，无 doctype/html/head/body；根 ID 唯一，样式限定在根内，优先无脚本的 HTML/CSS/SVG。成功写入后，使用工具返回的规范引用路径或已核实绝对路径，在助手正文独立一行输出内联引用，例如本产品的 `::visualize{"path":"<已核实的绝对路径>/style-options-inline.html"}`。引用必须出现在风格确认前的助手消息中，再继续调用 ask_user；不能只留在工具输出、代码块或整套课件完成后的最终回复里。使用正常消息宽度，不为四个方案启用 wide。
2. **缺少、禁用或无法读取 visualize，或内联展示明确失败**：沿用现有方案，用 write 保存完整、自包含的 `style-options.html`，通过已核实路径的普通 Markdown 文件链接展示，再用 ask_user 选择。复用相同四套方案的内容和响应式布局；内联片段与完整文件使用不同路径，不能覆盖已引用片段来伪装降级成功。无需额外生成两份预览，只有实际降级时才写完整文件。文件也不可访问时简述原因，列出同一组风格名、配色和气质供选择。
3. 两条路径均使用同一组 A–D 名称及说明调用 ask_user，并等待用户真实选择；不把卡片高亮、浏览状态或默认选项当作用户确认。不在预览内另造一套提交按钮或追问通道，不增加第二轮风格确认。已有明确风格或用户让模型自行决定时直接确定 DESIGN，跳过整轮预览与询问。

风格预览属于过程内容，不调用 `publish_file`。内联路径不额外附下载链接或成果卡；降级路径才展示普通文件链接。使用 HTML/CSS/SVG，不依赖外部脚本、图片网络请求或跟踪请求，文本正确转义，图片与装饰以轻量方向示意表达。

### 窄栏布局

以消息容器的实际宽度布局，从 320px 可读开始：顶层透明、width:100%、min-width:0，不加整块预览外壳。方案名称、色板与说明放在示意图外，使用正常文字尺寸并允许换行；不用缩小整个 1280×720 页面来塞四张卡。16:9 示意只展示代表性标题、图文分区与主题元素，不塞完整课文或密集公式。

可使用下列根内布局骨架；这是响应式规则，不是固定视觉模板。按当前预览替换根 ID，四个方案容器使用 `.style-option`，示意区使用 `.style-sample`：

```css
#cw-style-options {
	width: 100%;
	min-width: 0;
	container-type: inline-size;
}
#cw-style-options,
#cw-style-options * {
	box-sizing: border-box;
}
#cw-style-options .style-grid {
	display: grid;
	grid-template-columns: minmax(0, 1fr);
	gap: 12px;
}
#cw-style-options .style-option {
	min-width: 0;
	overflow-wrap: anywhere;
}
#cw-style-options .style-sample {
	width: 100%;
	aspect-ratio: 16 / 9;
}
#cw-style-options .style-palette {
	display: flex;
	flex-wrap: wrap;
	gap: 6px;
}
@container (min-width: 640px) {
	#cw-style-options .style-grid {
		grid-template-columns: repeat(2, minmax(0, 1fr));
	}
}
```

320–639px 单列，640px 起两列；不支持容器查询时自然保留单列。降级完整 HTML 补齐 viewport 元信息和正常页面边距，仍用这套容器布局。禁止固定外层宽度、横向滚动、固定高度裁切、vh 高度或通过 transform 缩小文字。SVG/图片随示意区宽度适配，必要说明留在外部，避免小字；色板加文字名称，含义不只靠颜色。外部标签与容器遵循 visualize 的深浅主题，样张及色板保留待选课件的目标颜色。

保存前轻量核对单列/双列、长中文名称换行和内容高度；不为四套示意额外逐页截图或开启多轮美化。有实际窄栏溢出时，只修当前预览。没有实际渲染证据时不声称已验证所有宽度。

预览围绕相同的本课内容展示正文层级与图文关系。用候选 spec 的 cssVariables 生成预览色板。背景和装饰是风格选择的一部分，按下面的顺序沿用到成稿。

1. **展示前保存。** 按候选标识保存实际 spec、背景源和示意对应的页型。网格、线稿、轮廓等图形背景使用可写入 EN 的矢量图稿，由 [motifSvg](vector-graphics.md#主题矢量图稿) 生成风格卡中的图层。CSS 负责样卡的尺寸、排版和图层位置；网格等主题图案从图稿生成。若照片或纹理使用已选素材，预览和成稿复用同一资源。待搜图或生图的候选明确标注“图片待选”，示意主图位置与裁切方向。
2. **选定后取回。** 按实际选中的标识加载保存的 spec，将背景源、覆盖范围和放置位置写入 DESIGN，明确对应的正文页。与样卡对应的正文页优先采用原版图稿，其余普通正文沿用同一图稿或它的变体。先调整位置、范围或透明度，为密集文字、主图与控件留出净区。需要整页净底或封面独立构图时，在 DESIGN 写明例外页及用途。
3. **写入时复用。** 对采用该背景的原生页用取回的 spec 调用 apply。在已有批次自检中，按 DESIGN 核对本批正文实际使用的原图、变体和净底例外。已选图稿需要调整时从保存的节点派生。HTML 页按该页规划复用同一图源。直接出稿的任务只准备实际采用的一份 spec。

方向示意只需足以比较的四个简洁方案；不制作课件互动、动画、整套页面源码或完整素材库。用户确认后直接进入首批制作，不再单独重画所选风格预览。

## STORY 与 DESIGN

专业图先按 [学科专业技能接入](subject-integration.md) 匹配任务；物理图执行 [物理图接入](physics-integration.md)。在逐页任务中记录 figureKey、目标 pageKey、专业技能、研究对象、假设、已知量与单位、定量/定性、关键关系、初始/变化/揭示状态、目标图区及检查点。与素材和互动栏合并记录，不另写第二套计划；先定模型，再执行本批专业图生成、图级审阅与登记，取得真实产物后插入对应页。按任务匹配当前会话可用的学科技能。

已有 EN 教学设计时，先读取同一 `planUid` 的当前内容，承接用户已确认的版本；如出现影响课件的实质变化，先展示变化并请用户确认。`STORY.md` 记录该 `planUid` 及课件规划所需摘要，`DESIGN.md` 记录视觉方案；两者不复制完整教案，也不替代云教案成为第二份教学设计产物。两份简短规划在同一轮完成；页面表用短句表达已有教学内容，不把每个维度展开成长段说明。在 STORY 记录个人规范来源、版本或可核对的读取状态、适用范围与缺口，加入简短规则对应表；每条适用已确认规则对应 pageKey、具体落实与检查方法。教学路径、同图变式、题答位置及显示时机进入逐页任务与动画栏；角色样式、个人页型和稳定颜色语义进入 DESIGN 与共享 spec。不复制整份私有规范，不另建重复的规划文档。

`STORY.md` 开头写受众、课时、教学目标与范围，注明已核实的材料来源和仍缺失的信息。页面表每页一行短句，使用以下栏目；这些是规划记录，不是新增工具参数，不另写逐页设计文档：

| 栏目               | 需要确定的内容                                                                                                                                                             |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 页码与标题         | 页序及稳定 pageKey，供源稿、草稿和真实 slideId 对应                                                                                                                        |
| 学习任务与必要内容 | 学生要做什么、必须保留的原文、条件或关键推理；简记需突出的概念/证据/变化项及初始可见或后揭示，不复制整段正文 |
| 载体与互动判定     | 每页明确 HTML / 原生；适合操作的页写“操作 → 反馈 → 结论，重置到什么状态”，原生页简记为何整体阅读或教师示范更合适                                                           |
| 动画与推进         | 原生页写常显对象、各步目标内容、点击/自动接续、具体效果及所需过渡；例如“题干常显；点击1淡入模型；点击2淡入结论”；静态写理由。HTML 页写核心状态变化，不额外编造 EN 元素动画 |
| 第一焦点与图文关系 | 主体是大引文、观察图、模型还是关系图，辅助说明贴近哪个对象；无需图时注明阅读或作答任务，装饰背景不充当教学主图 |
| 教学素材与来源     | 按 pageKey 写明情境图、观察图、模型或视频的教学用途及来源。按需记录专业技能及图标识/生成状态、已登记素材、搜图关键词与目标比例或原生绘图方式。纯阅读或演算可写“无需配图”。                                                                               |

按 [互动页判定](interactive.md#逐页选择与互动分布) 逐页评估，优先将适合选择、操作和反馈的学习任务做成 HTML，而非先铺原生页、最后另加一个活动。表后简记总页数、HTML 页码与占比、计划原生动画页码和核心配图页码；规划时若大量适合操作的页仍为纯展示，先调整这些页的载体。该统计用于发现遗漏，不设固定比例、不凑页数。封面、完整阅读或无需操作的内容按实际任务保留原生。

按 [视觉层级与密度](visual-rules.md) 区分讲稿与上屏内容，不计算字数、填充率、留白或配色占比。原文、转述与教学解释分清，精确引句、数据或段落编号核对实际材料，不以搜索摘要代替原文。按 [教学动画](animations.md) 将目标内容和效果直接转成当前页的 animationPlan，不能只写“逐步”而把实现留到末尾。分步揭示不能提前泄露答案，开放问题不强制唯一答案。

规划与落实分别记录：在已有批次进度中将 pageKey 对应到真实 slideId，记录 HTML 插入及验证、原生动画回执、核心图片的实际来源、assetId 和写入结果。专业图同时关联 figureKey、真实源稿/产物、assetId 和实际 slideId/elementId（以回执为准），区分已生成、已检查、已登记和已插入；失败时保留这些证据并局部恢复。完成后按原计划核对差额；漏提交、失败或未知的项保持待补/待查，不能为了匹配实际产物把原定动画改成“其余静态”、把活动改成讲解或删掉配图需求。因用户意见或教学内容变化调整方案时，同步记录变更理由。

`DESIGN.md` 按 [整套视觉规格与原生复用](design.md#整套视觉规格与原生复用) 写一次共用视觉规格，配套 spec 随已有批次草稿保存；承接风格预览、原生正文与 HTML 互动页。其中单列[背景与装饰方案](design.md#背景与装饰方案)，按整套默认、页型或具体 pageKey 记录例外。不展示风格选项时，有适用个人规范则先沿用其已确认方向，通用配色仅补未限定部分；无个人方向才按 [通用配色与风格变化](themes.md#通用配色与风格变化) 在现有规划内直接确定方向。不强行随机换掉个人色彩语义，不增加询问或候选渲染。页序和总数仅用于 STORY 与工具编排，不在课件画面绘制页脚或页码。

从 STORY 的教学素材栏按批准备情境图、解释图等，按[素材准备与复用](design.md#素材准备与复用)选图并对应到教学节点。从 DESIGN 的背景与装饰方案取本页适用的底色、图稿或背景图片。两者按页合成，共用图稿随草稿复用。首批实际写入已安排使用主题背景的正文页，再用首张代表页截图核对其效果。

模型按内容关系直接创作；同类关系复用本课已经确定的结构与样式，局部构图随任务变化，不规定固定页型或装饰配额。保持当前批次草稿和已有共享定义即可，不为复用新增逐页设计文件或独立模板生产阶段。

## 尽早打开并分批制作

调用 `tools.courseware_lifecycle({action:"createBlank",name:"课题"})`，用 manifest 获取真实课件和页面信息；以工具 schema 为准补齐所需参数。createBlank 自身会打开课件；需要定位时使用 `tools.courseware_present({coursewareId,action:{kind:"gotoSlide",slideId}})`，slideId 从 manifest 或写入回执获取。createBlank 可能已有空白页：保留它到全部目标页面创建完成，在统一检查阶段确认无内容后再单独删除，不能删除用户原有内容。

按每页的阅读顺序和主图位置确定构图，再按每批 3–4 页制作：继承 DESIGN 与已有共享结构 → 按 STORY 的载体和内容关系构图 → 准备本批必要主图 → 原生页组合正文与 animationPlan，HTML 页组合任务、反馈与 verification → 一起暂存本批草稿，一次自检内容、图片与动画计划是否进入真实参数 → 同一次 codemode 按页序 await 独占 insertSlideLayout 或 insertHtmlPage，页级捕获错误后停止 → 正常结束以持久化草稿和成功回执。失败按 [局部修复](layout.md#失败后的局部修复) 处理，后续只继续未完成页。一次编辑工具调用仍只插入一页，不把多个插页操作塞进同一个 operations 数组，也不并行写入以免页序不确定。批次大小服从代码、接口与素材预算，最后不足一批时按实际页数提交；独立内容修改可按相同页数分批合并。

工具内部照常编译、物化图片、写入和自动回读；这些运行时检查不等于 Agent 主动验收。创建阶段记录真实 slideId、内容写入结果和动画配置结果，按 [动画回执规则](animations.md#失败撤销与交付) 判断。首批出现第一张有代表性的普通正文页后，按 [正文风格校准](review.md#正文风格校准) 前移一次抽查，纠正会复制到后续页面的样式缺口；不是每批校准。其余静态问题、截断预览、动画待修项和待补读项在已有进度记录，完成创建后集中处理；不为轻微排版细节逐页返工。尚未写入的参数/编译错误只修到可创建，写入未知时先读实际状态，不盲目重试。图片按批获取，同一对象与主题装饰复用已确认的 assetId，素材缺失不能用空框冒充完成。

全部目标页面创建完成后再进入 [检查与交付](review.md)。如果存在无法创建的页面，如实保留未完成清单，不宣称全篇完成，也不提前用已完成部分替代整份课件验收。

使用回执中的 slideId 标识页面。不要把标题当唯一标识，也不把整个生成流程再做成一个固定多步工具或第二套 Agent Loop。
