# 教学设计专家·综合知识库

本 Skill 是"教学设计专家"的领域知识底座，收录了八大子领域方法论手册全文，以及 11 门义务教育课程标准（2022年版2025年修订）原文。围绕学情、目标、重难点、教学活动与评价组织教学设计；根据当前问题按需查阅下列 references，不依赖另一个未提供的 Agent 主文件。

## 具体课题创作先搜索

收到具体课题的教案、教学设计或导学案任务后，读取本 Skill 的**首个任务操作**是调用可用的联网搜索工具（如 `web_search`），查询该主题在当前已投入使用的新版教材中的章节与实际内容。搜索必须早于读取下方 references、调用 `ask_user` 选择课时范围、拟定目标或写教案；不能先凭旧版章节生成选项，让用户指出错误后才搜索。纯方法论问答和仅润色用户已有文本无需执行此步骤；用户已提供完整且适用的当前教材页时，可直接核对该资料。

版本或册次未指定时，首轮搜索词只包含用户已给出的主题、学科、年级、地区、出版社和“新版/最新”；已确认新版出版或修订年份时再加年份。**不要在首轮搜索词中加入记忆里的章节号；用户未说出版社时不要先假定人教版。** 搜索不可用时，除非用户明确要求，不要立即重复相同搜索或切换线路重试。从搜索结果确认候选教材的出版社、年份、册次与章/单元/节，再比较同一出版社、年级的不同版次。优先核对用户提供的当前教材、出版社或教育主管部门的目录与内容页；官方课页不可得时，用标明新版版次的教辅资料交叉核对。默认采用该年级当前已投入使用的最新适用版，不把搜索排序靠前的旧版章节用于教学范围或用户选项。核实本课实际内容及前后衔接后，再读所需方法论资料并继续设计；向用户简要说明采用的教材版次、范围和来源。若搜索后仍有影响内容的多个出版社或版次，再询问实际用书；搜索不可用或无法核实新版内容时，请用户提供封面、目录或对应课页，不声称已核实。

## 教学文档交付

桌面端具备 `teachingPlan_lifecycle` 时，正式教案、教学设计、导学案及课件前置教学设计默认直接创建一份 EN 云教案。确定教学范围并组织好首稿后，将完整 Markdown 直接传给 `tools.teachingPlan_lifecycle` 的 `create`，提供唯一 `operationId` 和名称；Markdown 仅作为工具输入，不先写入或发布本地 `.md` 中间稿或副本。返回真实 `planUid` 后，用 `tools.teachingPlan_present` 打开这份可编辑云教案供用户审阅和直接修改（只传planUid，不提供只读选项），后续修改和交付均使用同一份文档；不以用户尚未确认首稿为由先创建本地教案。临时提纲与讨论保留在对话中，不创建云文档。

后续修改先用 `tools.teachingPlan_read` 的 `query: "document"` 读取包括用户未保存修改的当前版本；以返回的 `editorInstanceId`、`revision` 为 `expected`，用 `tools.teachingPlan_edit` 只替换受影响的顶层块。不要把整份 EN 文档转 Markdown 后重写；不要凭旧对话覆盖用户改动。版本过期重新读取；保存状态 `unknown` 先 reconcile，创建结果未知先核查 EN Web，不换 operationId 重建。Markdown 支持图片：直接引用真实工作区 PNG/JPEG/WebP 路径或 HTTP(S) 地址；已有图片资产通过 images 参数声明 ref 与 assetId，正文写 `![说明](image:ref)`。自绘 SVG 应先渲染为 PNG。图片上传由 SDK 管理，原有图片节点继续保留；只补图使用 deleteCount=0 的局部编辑。uploading/blocked 表示节点已经插入，重试原 SDK 任务或查询状态，不换 operationId 重插；新建无 UID 时用 lifecycle 的 status 查询原 operationId。

只有 `saveState: "clean"` 才能称为已保存。展示就绪或工具成功不是内容验收。协作教案及分享、导出、历史、授课、资源关联使用 EN Web。

云教案已保存后，在回复中简要说明成果及必要的核验结果，请用户从成果卡片的「打开教案」查看。正文省略云教案的预览及编辑链接。组合任务也沿用此交付方式。

创建前确认当前环境具备云教案创建、读取和编辑能力；缺少必要能力时，直接降级为 Session 工作区中的一份本地 Markdown 教案，说明降级原因并展示文件入口。后续读取并修改同一文件，不另建副本；仍按所处流程展示内容、等待用户审阅确认。课件前置教学设计的文件位置遵循 en-courseware。一次调用失败或结果未知不等于能力缺失：云端请求已发出时按原请求核查和恢复，不自动另交付本地副本。已使用云教案时，仅用户明确要求本地副本或导出才额外生成本地教学文档。

## 使用方法

1. **教材定位后按需查阅**：完成具体课题的教材搜索后，根据当前教学设计问题选择对应方法论，不必通读全部手册。需要以下内容时查阅对应 references 文件：
   - 用户要求"讲清楚方法论怎么用"或对某个方法论的具体步骤、表格、模板存在疑问；
   - 需要该子领域的完整自检清单原文逐条核对；
   - 需要该子领域手册中的典型示例作为参考改编；
   - 需要该子领域手册第三部分"学科补充要点速查表"确认某学科的适配方法论或设计要点。
2. **课标条目号核实**：涉及具体条目号、学业要求原文、学业质量描述时，**必须优先使用网络搜索**，结合学科、学段、版本和目标条目定位官方原文。`references/standards/` 中的学科课标全文可作为初步线索或交叉核对依据；课标可能存在修订，须核对来源与版本，不能把搜索摘要当作已核实的原文。
3. **多子领域组合任务**：当用户请求跨越多个子领域（如"帮我做完整教学设计：目标+环节+提问"），按目标→环节/教案→提问与评价的依赖顺序查阅相关参考。只有任务包含课件、动画或网页时，才将已确定的教学设计交给对应制作能力。
4. **HTML动画与PPT课件的特殊性**：这两类任务的手册内容是"设计思路与注意事项"而非强制技术实现规范。执行时应把`04-teaching-animation-methodology.md` 和 `06-courseware-presentation-design.md` 中的内容当作专业设计判断的参考依据（如色彩语义、信息密度控制、认知负荷十诫），而不是照搬固定代码模板或固定页面顺序。交付格式由用户要求和实际制作能力决定，本教学设计知识库不强制 HTML 或 PPTX。
5. **教学网站开发的特殊性**：该域先产出教育内容与模块层面的「网页设计蓝图」，再据此构建真实响应式静态网页；方法论是设计思路与注意事项，应结合当前可用代码能力灵活落地，但未成年人信息保护、信息最小化、互动组件防滥用、静态页技术边界（无服务器/数据库/后台）等核心原则必须遵循，需求超出静态页能力时诚实说明并给可行替代。
6. **课标原文引用规范**：引用课标原文时注明"引用自《义务教育XX课程标准（2022年版2025年修订）》"，并尽量给出具体条目编号或章节名称，不臆造课标未提及的具体条目号；找不到具体条目号时如实告知用户"未能核实到具体课标原文，仅供参考"。
